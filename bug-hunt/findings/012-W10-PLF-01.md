## Patch

**WONTFIX — false positive. `BSD` IS a CMake variable; the original code is correct.**

- **Why it's not a bug:** CMake sets `BSD` to the OS name during platform initialization —
  `Modules/Platform/FreeBSD-Initialize.cmake` does `set(BSD "FreeBSD")` (likewise
  OpenBSD/NetBSD/DragonFly), and `CMakeSystemSpecificInitialize.cmake` does `unset(BSD)`
  first so it's empty elsewhere. These run inside `project()`, long before the uses at
  lines 250/487. So on FreeBSD `BSD` is truthy and the original `if(NOT BSD …)` /
  `elseif(BSD AND NOT APPLE)` already pick the right branches; on Windows/macOS/Linux `BSD`
  is empty and they correctly fall through.
- **Empirical proof (CMake 4.1, no BSD/Apple hardware — cross-target probe with `project(NONE)`
  + `-DCMAKE_SYSTEM_NAME=…`):**
  - `target=FreeBSD` → `BSD=FreeBSD` → `NOT BSD`=FALSE (system deps), `BSD AND NOT APPLE`=TRUE (FreeBSD CPack applied) ✓
  - `target=Darwin`  → `BSD=`(empty), `APPLE=1` → bundled deps, no FreeBSD CPack ✓
  - `host=Windows`   → `BSD=`(empty) → bundled deps, no FreeBSD CPack ✓
- **Where the agents went wrong:** all six assumed from general knowledge that CMake has no
  `BSD` variable. It is an old, lightly-documented feature (the `*-Initialize.cmake` platform
  modules), but it is real and present. The grep "BSD never set in the project" was true but
  irrelevant — CMake itself sets it.
- **Files changed:** none. The exploratory branch `fix/detect-bsd-platform` (`b64a677`,
  a redundant `if(CMAKE_SYSTEM_NAME MATCHES "BSD") set(BSD TRUE)`) was reverted — remote and
  local branch deleted; `main` is untouched.
