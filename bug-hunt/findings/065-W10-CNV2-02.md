## Patch  _(fill when fixing)_

- **Root cause:** Markdown is imported as **rich text** — `updateContents()` parses
  `text/markdown` via `QTextCursor::insertMarkdown()` (documenthandler.cpp:959-960, 1112-1113),
  so headings/bold/italic/links/images become real document formatting. But `saveAs()`
  (documenthandler.cpp:1138-1177) only distinguished HTML from everything else:
  `isHtml` is true for `.html/.htm/.xhtml`, and the writer was
  `file.write((isHtml ? doc->toHtml() : doc->toPlainText())...)`. A `.md` file took the
  `toPlainText()` branch, which flattens all formatting. `toMarkdown()` was never called.
- **Fix:** Add an `isMarkdown` flag (`.md` / `.markdown`, case-insensitive) and a third
  output branch: `isHtml ? toHtml() : isMarkdown ? toMarkdown() : toPlainText()`. The Android
  path keeps `isHtml = true` (and `isMarkdown = false`). `toMarkdown()`'s default
  `MarkdownDialectGitHub` matches the dialect `insertMarkdown()` uses on import, so the
  round trip is symmetric. The file-open mode is unchanged (Markdown writes as text, like
  plain text did).
- **Files changed:** `src/documenthandler.cpp` (saveAs: +3 lines, 1 line changed).
- **Verification:** Empirical, compiled and run against Qt 6.11.1 (QPrompt's shipping
  version — confirmed identical in CraftRoot and the mingw_64 kit). A standalone program
  drove the exact calls: `QTextCursor::insertMarkdown()` on import, then `toPlainText()`
  (old) vs `toMarkdown()` (new) on save.
  - **Bug reproduced:** the imported document genuinely holds the formatting (`toHtml()`
    shows `font-weight:700`, `font-style:italic`, `<a href`, `<img`), yet the old
    `toPlainText()` output flattens everything — `# Heading`→`Heading`, `**bold**`→`bold`,
    `[link](url)`→`link`, list markers gone — and re-opening that saved text does NOT match
    the original.
  - **Fix proven:** under the real `windows` QPA platform, `toMarkdown()` preserves all
    eight feature classes tested — heading, **bold**, *italic*, `inline code`, link, image,
    list, blockquote.
  - **Caveat noted during testing:** under headless QPA plugins (`offscreen`/`minimal`)
    bold/italic were dropped because those platforms have no font database for the markdown
    writer to confirm boldness; with the real Windows font database the emphasis emits
    correctly. Import and export both default to `MarkdownDialectGitHub`, so the round trip
    is symmetric.
- **Commit / PR:** `9053883` on branch `fix/save-markdown-formatting` (cut from `main`).
