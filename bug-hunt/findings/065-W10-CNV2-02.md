## Patch  _(fill when fixing)_

- **Root cause (two-sided, platform-split — the report only saw half):** Markdown
  round-tripping is broken on both load and save, and the symptom differs by platform.
  - **Load** (documenthandler.cpp:959): a file is parsed as Markdown only when
    `mime.inherits("text/markdown")`. Empirically (Qt 6.11.1), Qt's **bundled** MIME
    database — used on Windows and macOS — types `.md`/`.markdown`/`.mkd` as
    `text/x-web-markdown`, which does **not** inherit `text/markdown` (and `text/markdown`
    is not even a registered type there). So on those platforms `.md` falls through to the
    `else` branch → `updateContents(data, Qt::AutoText)` → `cursor.insertHtml()`
    (documenthandler.cpp:1007, 1118-1119): the raw Markdown is loaded as **literal text**,
    never rendered.
  - **Save** (documenthandler.cpp saveAs): only `isHtml` (`.html/.htm/.xhtml`) vs
    everything-else; `.md` was written with `toPlainText()`. `toMarkdown()` was never called.
  - **Net effect:** on Linux (system MIME db has `text/markdown`) `.md` loads as rich text,
    so save-as-plaintext silently strips all formatting — the reported data loss. On
    Windows/macOS `.md` loads as literal text, so the report's specific scenario does **not**
    reproduce; worse, a naive save-only fix (toMarkdown on the literal-text document) would
    **escape** the markup (`# `→`\# `, `**`→`\**`), corrupting the file.
- **Fix (both sides, keyed off the same rule):**
  1. Load: accept `text/x-web-markdown` in addition to `text/markdown`, so `.md` parses as
     Markdown on every platform.
  2. Save: detect Markdown with the same MIME check
     (`mimeTypeForFile(path, MatchExtension).inherits(text/markdown | text/x-web-markdown)`)
     and write `toMarkdown()`. Three-way writer: `isHtml ? toHtml() : isMarkdown ?
     toMarkdown() : toPlainText()`. Android keeps `isHtml = true`/`isMarkdown = false`.
     Import (`insertMarkdown`) and export (`toMarkdown`) both default to
     `MarkdownDialectGitHub`, so the round trip is symmetric.
- **Files changed:** `src/documenthandler.cpp` (load: +4/−1; saveAs: +6/−1; one writer line).
- **Verification:** Empirical, compiled and run against Qt 6.11.1 (QPrompt's shipping Qt —
  identical in CraftRoot and the mingw_64 kit), under the **real `windows` QPA platform**.
  - **Bug reproduced:** the imported rich document genuinely holds formatting (`toHtml()`
    shows `font-weight:700`, `font-style:italic`, `<a href`, `<img`); old `toPlainText()`
    flattens everything and re-open does not match the original. Confirmed the Windows load
    path resolves `.md` to `text/x-web-markdown` and previously hit `insertHtml()`.
  - **Regression averted:** a save-only `toMarkdown()` on the Windows literal-text document
    produced `\# Title … \**bold**` (escaped/corrupted) — caught before shipping; the
    two-sided fix avoids it by parsing `.md` as Markdown first.
  - **Complete fix proven:** with both changes, load predicate is true for `.md/.markdown/.mkd`
    and false for `.txt/.html`; save routes `.md`→toMarkdown, `.html`→toHtml, `.txt`→toPlainText;
    full round trip preserves heading, **bold**, *italic*, `code`, link, image, list, blockquote
    with **no backslash escaping**, and is stable on a second pass.
  - **Note:** under headless QPA plugins (`offscreen`/`minimal`) `toMarkdown()` drops emphasis
    because they lack a font database; all results above use the real `windows` platform.
