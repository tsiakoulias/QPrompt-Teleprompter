## Patch  _(fill when fixing)_

- **Root cause:** `AbstractUnits` (src/abstractunits.hpp) declares `QML_UNCREATABLE` but
  no `QML_ELEMENT`/`QML_NAMED_ELEMENT`. Per Qt, `QML_UNCREATABLE` only marks an *already
  registered* element as uncreatable — on its own it registers nothing. The old
  `qmlRegisterUncreatableType(... "Units" ...)` in main.cpp:219 is commented out. The class is
  in the `com.cuperino.qprompt` QML module's SOURCES (src/CMakeLists.txt:79 → qt_add_qml_module
  URI com.cuperino.qprompt), but with no element macro `qmltyperegistrar` skipped it. QML
  refers to the type as `Units` (e.g. `duration: Units.ShortDuration`), so those references
  resolved to `undefined` and the animations/timers fell back to default timings.
- **Fix (revised after maintainer review on PR #481):** The first version added a one-line
  `QML_NAMED_ELEMENT(Units)`. The maintainer (Cuperino) preferred a cleaner approach: since the
  values don't need to be abstracted, **rename the class `AbstractUnits` → `Units`** and the file
  `abstractunits.hpp` → `units.hpp`, then plain `QML_ELEMENT` registers it under `Units` (C++ and
  QML names match — no `QML_NAMED_ELEMENT` needed). `QML_UNCREATABLE` is kept. Updated the include
  in `main.cpp` and the source list in `src/CMakeLists.txt` to match.
- **Files changed:** `src/abstractunits.hpp` → `src/units.hpp` (rename; `class Units`, `QML_ELEMENT`),
  `src/main.cpp` (include + stale comment), `src/CMakeLists.txt` (source list). 3 files, +5/−4.
- **Verification (full build, real toolchain):** Built with the project's actual toolchain
  (MSVC VS18 `cl.exe` + CraftRoot Qt 6.11.1, configured Ninja tree). `grep` confirms **zero**
  remaining `AbstractUnits`/`abstractunits` references. The regenerated
  `build-craft/src/qprompt_qmltyperegistrations.cpp` now emits
  `qmlRegisterTypesAndRevisions<Units>("com.cuperino.qprompt", 1);` +
  `qmlRegisterEnum<Units::Durations>(...)` (the whole block was **absent before**, registering
  every other type but `Units`). `units.hpp` (moc+registration) and `main.cpp` compile (exit 0);
  the **full `QPrompt.exe` links** (exit 0). So bare `Units.<Duration>` now resolves at runtime.
- **Separate issue (NOT fixed here):** several QML sites use bare `Units` with *Kirigami*
  property names — `Units.smallSpacing`, `Units.longDuration`, `Units.mediumSpacing` — and a few
  capitalized typos `Units.SmallSpacing` / `Kirigami.Units.SmallSpacing`. None of those are
  members of `AbstractUnits::Durations`; they should be `Kirigami.Units.smallSpacing` etc. This
  fix does not address (or regress) them — they were undefined before and remain so. Worth its
  own ticket. Many live in src/kirigami_ui/EditorToolbar.qml + PrompterPage.qml.
- **Commit / PR:** `fc52016` on `fix/register-units-qml-type` (PR #481; force-pushed over the
  original `QML_NAMED_ELEMENT` commit to apply the maintainer's requested rename).
