## Patch  _(fill when fixing)_

- **Root cause:** `search()` has a `loop` flag that controls whether it wraps around
  the document when no further match is found. Only `replaceAll()` calls it with
  `loop=false` (it walks the matches once and stops). The plain-text branch gates the
  wrap-around on `loop`, but the **regex branch ignored it** (documenthandler.cpp:1552 vs
  1567). So regex Replace All wrapped back to the end every time matches were exhausted;
  when the replacement also matches the pattern, the document keeps growing and the
  do-while never terminates — 100% CPU hang.
- **Correction to the claim:** the "stale `selectionStart` in plain-text replace" mechanism
  the report describes does **not** hang — the plain-text branch's `loop` guard already
  handles it (each original match is replaced once, going backward). The real, verified
  defect is regex-only. opus/opus-ultra had it right ("regex do-while can loop forever").
- **Fix:** Gate the regex wrap-around on `loop`, identical to the plain-text branch.
- **Files changed:** `src/documenthandler.cpp` (1 line, search()).
- **Verification:** Static — only `replaceAll` passes `loop=false`; Find Next/Previous/Match
  all use the default `loop=true`, so interactive wrap-around is unchanged. Regex Replace All
  now terminates. (Runtime test available on request via the local build.)
- **Commit / PR:** `56cd3ec` on `fix/replace-all-regex-loop`. Fixes this and its duplicate
  `222-LOG-06`.
