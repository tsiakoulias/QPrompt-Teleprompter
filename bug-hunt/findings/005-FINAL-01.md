## Patch  _(fill when fixing)_

**WONTFIX — false positive (ancestor-context id resolution).**

- **Why it's not a bug:** TimerClock is instantiated as `TimerClock { id: timer }` in
  `src/prompter/PrompterView.qml:218-219`. Inside `TimerClock.qml`, the unqualified `timer`
  isn't a local id, so QML resolves it up the context hierarchy to that instantiation id —
  which *is* the TimerClock instance, the same `QObject` as the file's internal `id: clock`.
  So `timer.getTimeString(...)` ≡ `clock.getTimeString(...)` and `timer.elapsedMilliseconds = 0`
  ≡ `clock.elapsedMilliseconds = 0`. ETA and stopwatch work; nothing is broken.
- **Evidence:** The same mechanism is why `prompter`, `editor`, `overlay`, `root`, `screen`
  already resolve throughout `TimerClock.qml`. If cross-file context-id resolution didn't work,
  the entire component would be dead — not just lines 70/82/85.
- **Where the agents went wrong:** All six read `TimerClock.qml` in isolation and never checked
  the instantiation site. Classic ancestor-context-id trap.
- **Files changed:** none.
- **Verification:** static — `grep "TimerClock"` → only instantiation is `PrompterView.qml:218`
  with `id: timer`; that id is the same object that carries `getTimeString`/`elapsedMilliseconds`.
