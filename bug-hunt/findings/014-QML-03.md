## Patch

**WONTFIX — false positive (ancestor-context id resolution; the report is doubly wrong).**

- **Why it's not a bug:** `root` isn't a local id in `WindowDragger.qml`, so QML resolves it up
  the context hierarchy to `id: root` — the Kirigami `ApplicationWindow` declared in
  `kirigami_ui/main.qml:35` (and the `+windows`/`+android` variants). WindowDragger is a direct
  child of the toolbar `background` (`EditorToolbar.qml:135`), which is the footer of PrompterPage
  on `root`'s pageStack, so `root` is in scope. `root.x`/`root.y` are the window position — the
  `Settings` block even aliases `x: root.x`, `y: root.y` — so `root.x += deltaX` correctly drags
  the window. Same trap as [005-FINAL-01] (TimerClock `timer`).
- **The report is wrong on both points:** (1) `root` *does* resolve (it's the ApplicationWindow);
  (2) `property var window` is *not* ignored — the instantiation sets `window: root`, and the same
  WindowDragger's `cursorShape` binding uses `root.hideDecorators`. EditorToolbar references the
  ancestor `root.` ~175 times, including the dragger's own parent Rectangle
  (`root.background.__backgroundColor`, `root.__opacity`).
- **Verification:** Static — `id: root` in `main.qml:35`; `root.x`/`root.y` valid (aliased in
  Settings); WindowDragger nested directly under bindings that already use `root`. Empirical — ran
  the app with stderr capture: **zero** `root is not defined` errors despite the parent Rectangle's
  `root.*` bindings evaluating on every render (toolbar renders fine); the only ReferenceErrors are
  the unrelated `Units is not defined` from this build's base branch. QML id resolution propagates
  to child contexts, so the dragger's `root` resolves identically.
