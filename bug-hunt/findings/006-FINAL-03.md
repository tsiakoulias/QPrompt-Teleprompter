## Patch  _(fill when fixing)_

- **Root cause:** `3rdparty/breeze-icons` is committed as a gitlink (index mode `160000`,
  commit `434fd288`) exactly like the other seven submodules, but it is the only one with no
  matching `[submodule …]` block in `.gitmodules`. `git submodule update --init --recursive`
  reads `.gitmodules` to learn each submodule's path+URL, so it silently skips breeze-icons and
  the directory stays empty. `cmake/BreezeIconSubset.cmake:97-100` then hits
  `if(NOT EXISTS "${BREEZE_DIR}/icons")` → `FATAL_ERROR`, aborting configuration on every fresh
  clone, every platform.
- **Fix:** Add the missing `.gitmodules` entry (path `3rdparty/breeze-icons`, url
  `https://invent.kde.org/frameworks/breeze-icons.git` — same KDE Frameworks convention as the
  ecm/kcoreaddons/kirigami/kcrash entries), placed in the KDE-frameworks group.
- **Files changed:** `.gitmodules` (+3 lines).
- **Verification:** `git config --file .gitmodules --get submodule.3rdparty/breeze-icons.url`
  resolves the URL; `git submodule init 3rdparty/breeze-icons` (the mechanism `--init` uses)
  registers it — `registered for path '3rdparty/breeze-icons'` — where before it was unregistered.
  The pinned SHA `434fd288` is reachable on that remote. No compile needed (metadata-only).
- **Commit / PR:** `7843abb` on `fix/add-breeze-icons-submodule`.
